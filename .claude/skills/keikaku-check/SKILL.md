# 計画素案の点検

## 0　このスキルの前提・入力・出力

**単体では動かない。** 本スキルは点検の手順と判定の基準を持つものであり、
数値と成果品は `docs/北塩原村_第10期/scripts/` の側にある。

| 要るもの | 使いどころ |
|---|---|
| `soan_content.py`／`build_soan.py`／`build_soan_docx.js` | 計画素案の組立て |
| `shiryo_content.py`／`build_shiryo_docx.js` | 策定委員会資料の組立て |
| `data_zuhyo.py`／`build_zuhyo_daicho.py`／`sync_zuhyo.py` | 図の数値の正本と台帳 |
| `figures_map.py`／`build_figures.py` | 図の採番と作図 |
| `wbs_kakunin.py`／`build_wbs.py` | 確認事項の台帳（正本） |
| `verify_soan.py`／`verify_shiryo.py`／`verify_shukei.py`／`verify_wbs.py` | 自己点検 |
| `redteam_soan.py` | 走査（日本語でない文字・受託者の語・禁止表現・個人情報） |
| `estimate_pages.py` | 頁数の積算 |
| python-docx／openpyxl／matplotlib／Node の docx | 読み書き |

**入力**　計画素案 docx・策定委員会資料 docx・図表データ管理台帳 xlsx・
WBS進捗管理表 xlsx・算定スクリプト群・見える化の収録データ。

**出力**　①点検の結果（適合／不適合／要判断／未実施）②起票する確認事項
③素案そのものの是正。

**判定は4つに分ける。** 検出しただけで不適合にしない。

| 判定 | 意味 | 扱い |
|---|---|---|
| **適合** | 確かめて問題がない | そのまま |
| **不適合** | 直さなければ送付できない | 直してから進む |
| **要判断** | 規則には当たるが、文脈により適否が分かれる | 人が見て決める |
| **未実施** | 環境・資料がなく確かめられなかった | 合格にしない。理由を残す |

**「未実施」を「適合」に丸めない。** 走査できなかった範囲・実行できなかった
コマンドは件数として別に示す。

本環境では **LibreOffice が動かず docx を PDF に変換できない**。
したがって**紙面（改頁・表の分割・図の配置）の確認はつねに「未実施」**であり、
成果品を送るたびにその旨を書き添える。これを「適合」に丸めない。

## 1　まず機械で確かめる

**件数・章節・未確定箇所はいつも実物から数える。** 本スキルの本文に数を書かない。

```bash
cd docs/北塩原村_第10期
python3 scripts/verify_soan.py        # 計画素案
python3 scripts/verify_shiryo.py      # 策定委員会資料
python3 scripts/verify_shukei.py      # 集計仕様書
python3 scripts/verify_wbs.py         # WBS・確認事項
python3 scripts/redteam_soan.py       # 走査（自己試験つき）
python3 scripts/build_zuhyo_daicho.py # 図の数値と素案の表との突合
```

**終了コード0でなければそこで止まる。** 自己点検を持つスクリプトは
1件でも不適合があると終了コード1で終わる。

素案を作り直すのは、**素案を直したときだけ**でよい。

```bash
python3 scripts/build_soan.py && node scripts/build_soan_docx.js
python3 scripts/shiryo_content.py && node scripts/build_shiryo_docx.js
```

**中間JSONを作り直さずに docx を組まない。** 組立てのスクリプトは
元データより古い JSON を見つけると止まる。止まったら指示どおり先に
`build_soan.py` を実行する。

## 2　網羅性の8つの軸

軸はいずれも**原典**に置く。他団体が策定した計画は軸に用いない
（比較材料としてのみ用い、気づいた点は原典で確かめてから扱う）。
**他案件の数値・記述を本村の成果品に持ち込まない。用いるのは方法の構造のみ。**

| 軸 | 原典 | 点検の置き場所 |
|---|---|---|
| A 法定記載事項 | 介護保険法第117条第2項・第3項、令和8年法律第51号 | 素案 1-2・第5章 |
| B 基本指針の別表 | 国の第10期基本指針（案）別表11事項 | **素案 資6**・点検39 |
| C 制度改正 | 令和8年3月 全国課長会議資料、政令・告示 | 素案 1-8・点検41 |
| D サービス見込量 | 法第117条第2項第1号・第2号 | 素案 5-4・5-5 |
| E 保険料 | 法第129条ほか、政令 | 素案 5-7・5-10 |
| F 交付金 | 評価指標・全国集計 | 素案 2-8・5-9・6-3 |
| G 中山間・人口減少地域の特例 | 令和8年法律第51号、基本指針（案） | 素案 1-8の3・5-4(14) |
| H 図表 | 法第117条、基本指針の別表、交付金の評価指標 | **図表データ管理台帳**・素案 資8 |

明細は `references/checklist.md`。いずれの軸も「あるか・ないか」だけでなく、
**どの章節に・どの出所で・いつ時点の値で書かれているか**まで見る。

### 期待する項目は素案の側に置かない

**素案（資6など）を正本にして対比すると、素案から項目が落ちたときに
対比も同じだけ落ちる。** 期待する項目の一覧は点検スクリプトの側に持ち、
素案から読んだ一覧との差を見る。
資6から1項目を落としたときに不適合になることを、点検の受入れの条件とする
（点検39はこれを満たしている）。

### 語が当たっただけで「対応済み」にしない

制度改正の点検は語の走査で行うが、**当たったものは候補**である。
次を確かめてはじめて対応済みとする。

- 当たった箇所が、その事項を書くべき章節か
- 施行の時期・適用の年度が原典と合っているか
- 否定の文（「未反映である」「見込んでいない」）ではないか
- 数値・施策への反映まで及んでいるか（言及しただけになっていないか）

**「7区分化は未反映である」という文でも語は当たる。**

## 3　守るべき制約の走査

`redteam_soan.py` が計画素案と確認事項に当てる。走査は6本。

| 見るもの | 走査する語・形 | 判定 |
|---|---|---|
| 受託者の内部の仕組み・作業経過 | 受託者／本素案／協議用／修正指示書／確認事項No／固定値／実物から／再実行／章節ごとに／判定しています／スクリプト名／`.py`・`.js`・`.json` | 不適合 |
| 禁止表現 | に由来する／と整合する／1件も／有意差がないため／全国トップ級 | 要判断 |
| 個人情報 | 電話番号・メールアドレス・生年月日・被保険者番号の形 | 不適合 |
| 許容する文字の外の文字 | 日本語・英数字・記号の許容表に当たらない文字 | 要判断 |
| 半角・全角のゆれ | 少数側に寄っている記号 | 要判断 |
| ヘッダー・フッター・ページ番号 | 組立てのスクリプトに設定が残っているか | 不適合 |

**走査そのものの自己試験を必ず通す。** 4種の誤りを含む文字列を作って
走査にかけ、現に検出することを確かめてから本文を走査する。
**検出しない走査は点検の意味がない。**

**計画は村が定めるものである。本文にも見出しにも受託者を主語とする語を置かない。**

個人情報の走査は形のあるものに限る。
**氏名・住所・自由記述・画像の中の文字は機械では拾えない。**
委員名簿・事業所一覧・担当者の欄を加えるときは目で確かめる。
**成果品に載る表に、人を指す欄を置かない**という運用で防ぐ。

## 4　図表の管理

**同じ数値を2か所に別々に書かない。**

- 図の数値の正本は `data_zuhyo.py`。作図も台帳もここから読む
- **図表番号は `figures_map.py` が本文に現れる順から振る。**
  番号を画像の中や表題に焼き込まない（片方だけがずれる）
- 台帳（xlsx）は村が数値を直す場所。直した値は
  **`sync_zuhyo.py` で正本に取り込んでから**台帳を作り直す。
  取り込まずに作り直そうとすると、`build_zuhyo_daicho.py` が止める
- 図の数値と素案の表が同じ値を持つ箇所は台帳の02シートに出る。
  **どちらか一方だけを直さない**

## 5　どこまで進めてよいかの区分

| 区分 | 条件 |
|---|---|
| **協議用として送付してよい** | 機械の点検がすべて通り、未確定箇所に扱いが定まっている。未確定箇所（【要確認】【要設定】）が残っていてよい |
| **委員会に諮ってよい** | 上に加え、素案と委員会資料の数値が一致している（点検19・20） |
| **確定してよい** | 上に加え、未確定箇所が0、確認事項に未解決がない、法令が定める手続（意見公募ほか）を経ている |

**確認事項の「既定値」は協議を進めるための仮置きであり、確定の根拠にならない。**

## 6　確認事項を起こす前に

- **同じ問いが台帳（`wbs_kakunin.py` の `K`）にないかを語で探す**
- `K` は未解決、`SOLVED` は解決済みの記録。**入れる先を間違えない**
  （`K` の件数が増えていることを実物から数えて確かめる）
- 反映先は素案に**現にある**章節で書く（点検42がこれを見ている）
- **決着しない場合の当方の扱いを置く**

## 7　陥りやすい誤り

`references/pitfalls.md` に、実際に起きた誤りと手立てをまとめている。
特に次の5つは繰り返し起きている。

- **件数が0のときは、数えられているかを先に疑う**
- **点検を足したら摂動を与え、現に検出することを確かめる。**
  通ることではなく、落ちるべきときに落ちることを確かめる
- **同じ指標・同じ割合に2つの値や2つの分母を置かない**
- **ご指示は同じ区分の成果品すべてに当てる。1冊だけ直して終わりにしない**
- **同じ数値を2つの成果品に別々に書かない。1か所から引く**
