# 計画素案の点検

## 0　このスキルの前提・入力・出力

**単体では動かない。** 本スキルは点検の手順と判定の基準を持つものであり、
数値と成果品は対象リポジトリの側にある。次があることを前提とする。

| 要るもの | 使いどころ |
|---|---|
| `repo_paths.py` | 素案の場所と規模（`RP.DRAFT`／`RP.draft_label()`） |
| `build_plan_draft.py`／`build_plan_public.py` | 協議用素案・公表版の組立て |
| `build_soan_kisai_taihi.py`／`build_soan_kadai.py` | 網羅性の対比・未確定箇所 |
| `build_process_control.py` | 確認事項の台帳（正本） |
| `build_zuhyo_daicho.py`／`data_zuhyo.py` | 図の数値と図表集との突合 |
| `build_toc_pages.py`／`build_public_toc.py` | 目次のページ番号 |
| `tools/check_pages.py`／`tools/restore_unchanged.py` | 紙面の点検・差分の整理 |
| python-docx／openpyxl／matplotlib | 読み書き |
| docx の検証スクリプト | `validate.py`（場所は環境による。下記） |

**入力**　協議用素案 docx・公表版 docx・別冊の図表集 xlsx・算定スクリプト群・
受領資料の収録モジュール・業務工程管理表のソース。

**出力**　①点検の結果（PASS／FAIL／要判断／未実施）②起票する確認事項
③対比の成果品の更新 ④素案そのものの是正。

**判定は4つに分ける。** 検出しただけで不適合にしない。

| 判定 | 意味 | 扱い |
|---|---|---|
| **適合** | 確かめて問題がない | そのまま |
| **不適合** | 直さなければ送付・公表できない | 直してから進む |
| **要判断** | 規則には当たるが、文脈により適否が分かれる | 人が見て決める |
| **未実施** | 環境・資料がなく確かめられなかった | 合格にしない。理由を残す |

**「未実施」を「適合」に丸めない。** 走査できなかった範囲・実行できなかった
コマンドは件数として別に示す。

重大度は3段階で書く。**致命的**＝送付を止める／**重要**＝送付前に直す／
**改善**＝次の版で直す。

## 1　まず機械で確かめる

**件数・章節・未確定箇所はいつも実物から数える。** 本スキルの本文に数を書かない。

```bash
python3 -c "import repo_paths as RP; print(RP.draft_label())"   # 段落・表・図
python3 build_soan_kisai_taihi.py     # 記載事項の対比と網羅性
python3 build_soan_kadai.py           # 未確定箇所と確認事項の突合
python3 build_zuhyo_daicho.py         # 図の数値と図表集との突合
```

**終了コード0でなければそこで止まる。** 自己点検を持つスクリプトは
1件でも不適合があると終了コード1で終わる。

素案そのものを作り直すのは、**素案を直したときだけ**でよい。
既にある成果品を点検するだけなら作り直さない。

```bash
python3 build_plan_draft.py && python3 build_plan_public.py
```

docx の検証は必ず行う。検証スクリプトの場所は環境による。
**存在を確かめてから呼び、無ければ「未実施」と記す。**

```bash
V=${DOCX_VALIDATE:-/mnt/skills/public/docx/scripts/office/validate.py}
[ -f "$V" ] && python3 "$V" "output/第10期介護保険事業計画_協議用素案_令和8年8月.docx" \
            || echo "docx の検証は未実施（validate.py が見つからない）"
```

見出しを増減したとき、**及び本文・表・図が増減してページが動いたとき**は
目次のページ番号を作り直す。

```bash
python3 build_toc_pages.py        # 協議用素案
python3 build_public_toc.py       # 公表版
# 紙面の点検は PDF に変換してから（使い方は references/commands.md）
python3 tools/check_pages.py <pdf> <docx>
```

詳しい手順とコマンドは `references/commands.md`。

**始める前に `references/pitfalls.md` を一読する。** 実際に起きた誤りと
その手立てをまとめてある。新しい点検を置く前にも読む。

## 2　網羅性の8つの軸

軸はいずれも**原典**に置く。他団体が策定した計画は軸に用いない
（比較材料としてのみ用い、気づいた点は原典で確かめてから扱う）。

| 軸 | 原典 | 点検の置き場所 |
|---|---|---|
| A 法定記載事項 | 介護保険法第117条第2項・第3項、社会福祉法等改正法（令和8年法律第51号） | 対比 02シート |
| B 基本指針の別表 | 国の第10期基本指針（案）別表「確認すべき指標・状況」11事項 | 対比 03シート・素案 資料6 |
| C 制度改正 | 令和8年3月 全国介護保険・高齢者保健福祉担当課長会議資料 | 対比 04シート・素案 第1章第9節4 |
| D サービス見込量 | 法第117条第2項第1号・第2号 | 素案 第6章第2節・第3節 |
| E 保険料 | 法第129条ほか、政令 | 素案 第6章第6節・第7節 |
| F 交付金 | 保険者機能強化推進交付金等の評価指標・全国集計 | 素案 第3章第4節 |
| G 中山間・人口減少地域の特例 | 令和8年法律第51号、基本指針（案） | 素案 第1章第9節1・2 |
| H 図表 | 法第117条（量・回数）、基本指針の別表、交付金の評価指標 | 図表データ管理台帳・素案 資料7 |

各軸で何を確かめるかの明細は **`references/checklist.md`** による。
いずれの軸も「あるか・ないか」だけでなく、
**どの章節に・どの出所で・いつ時点の値で書かれているか**まで見る。

### 期待する項目は素案の側に置かない

**素案（資料6など）を正本にして対比すると、素案から項目が落ちたときに
対比も同じだけ落ちる。** 期待する項目の一覧は原典の側に持ち、
素案から読んだ一覧との差を見る。
資料6から1項目を落としたときに不適合になることを、点検の受入れの条件とする。

### 語が当たっただけで「対応済み」にしない

制度改正の点検は語の走査で行うが、**当たったものは候補**である。
次を確かめてはじめて対応済みとする。

- 当たった箇所が、その事項を書くべき章節か
- 施行の時期・適用の年度が原典と合っているか
- 否定の文（「未反映である」「見込んでいない」）ではないか
- 数値・施策への反映まで及んでいるか（言及しただけになっていないか）

**「7区分化は未反映である」という文でも語は当たる。**

## 3　守るべき制約の走査

計画素案・公表版のいずれも、**本文・入れ子を含む表・ヘッダー・フッター・
テキストボックス**を走査する。走査できなかった要素は件数で示す。
偽陽性を避けるため、個人情報は値の形（正規表現）で探す。

| 見るもの | 走査する語・形 | 判定 |
|---|---|---|
| 受託者の内部の仕組み・作業経過 | 受託者／本素案／協議用（公表版のみ）／修正指示書／確認事項No／固定値／実物から／再実行／章節ごとに／判定しています／スクリプト名 | 不適合 |
| 他団体の固有名称 | 収録している団体名の一覧から機械で作る（当連合・構成3町を除く） | 不適合 |
| 禁止表現 | に由来する／と整合する／1件も／有意差がないため／全国トップ級 | 要判断 |
| 個人情報 | 電話番号・メールアドレスの形 | 要判断（公的な連絡先は文脈による） |
| 許容する文字の外の文字 | 日本語・英数字・記号の許容表に当たらない文字 | 要判断 |
| 未確定箇所の表記 | ［　］以外の括弧（[ ]・【 】・〔 〕）で書いたもの | 不適合 |

**計画は広域連合が定めるものである。本文にも見出しにも受託者を主語とする語を置かない。**

個人情報の走査は電話番号とメールアドレスに限る。
**氏名・住所・自由記述・画像の中の文字は機械では拾えない。**
委員名簿・事業所一覧を加えるときは目で確かめる。

## 4　体裁と視認性

- 表の見出し行を各ページで繰り返す（`w:tblHeader`）。行を分割しない（`w:cantSplit`）
- 表頭に地色を敷く
- ［要協議］［要確認］［要内訳］は本文に残す。**確定しない値を推測しない**
- 前回計画（第9期）の図表レイアウト・フォント・表の体裁を維持する。
  **「第9期計画にない体裁」と決める前に、第9期の体裁を記した資料（資料7）を読む**
- 公表版は未確定箇所が1つでも残る間、表紙に「（体裁確認用）」と出る

## 5　2つの版の切り分け

**内容の正本は協議用素案である。** 公表版は協議用素案の docx を読んで組み替える。
本文・数値を別に持たないため、協議用素案を改めれば公表版も追随する。

公表版だけが持つのは、表紙・章の見出しの帯・目次の字下げ・
サービスの内容・用語の解説であり、**数値と本文は同じもの**である。

**「同じ docx を読んでいる」ことは、組み替えの途中で落ちていないことの
証しにはならない。** 落としてよい要素（「協議」判定の分析）を定めたうえで、
節の数・表の数・数値を突き合わせる。

## 6　どこまで進めてよいかの区分

| 区分 | 条件 |
|---|---|
| **協議用として送付してよい** | 機械の点検が通り、未確定箇所に既定値の扱いが定まっている。未確定箇所が残っていてよい |
| **体裁確認用として送付してよい** | 上に加え、目次のページ番号と紙面の点検が済んでいる |
| **公表版として確定してよい** | 上に加え、未確定箇所が0、確認事項に未解決がない、法令が定める手続（意見公募・都道府県の意見の聴取ほか）を経ている、対象の版が定まっている |

**確認事項の「既定値」は協議を進めるための仮置きであり、
公表の確定の根拠にならない。** 既定値は「保留」「公表の対象から外す」
「仮定を明示した協議用の試算」を選べる形にし、すべてに数値を置かない。

## 7　確認事項を起こす前に

- **同じ問いが台帳にないかを語で探す。** 台帳は業務工程管理表を正とする
- 別の成果品で起票したら、必ず業務工程管理表へ登録する
  （`sorted(x[0] for x in CHECK)` で欠番を出す）
- **番号が連続していても登録漏れは起きる。** 成果品の側で挙げた論点の集合と
  台帳の集合を突き合わせる
- **全件に「決着しない場合の当方の扱い（既定値）」を置く**
- 反映先は素案に**現にある**章節で書く

## 8　陥りやすい誤り

`references/pitfalls.md` に、計画素案の点検で実際に起きた誤りと手立てをまとめている。
特に次の4つは繰り返し起きている。

- **件数が0のときは、数えられているかを先に疑う**
- **同じ指標・同じ割合に2つの値や2つの分母を置かない**
- **ご指示は同じ区分の成果品すべてに当てる。1冊だけ直して終わりにしない**
- **同じ数値を2つの成果品に別々に書かない。1か所から引く**
