# 計画素案の点検（川崎町 第10期）

## 0　このスキルの前提・入力・出力

**単体では動かない。** 本スキルは点検の手順と判定の基準を持つものであり、
数値と成果品は `kawasaki_project/` の側にある。次があることを前提とする。

| `07_ソーススクリプト/build_zuhyo_daicho.py` | 図表データ管理台帳と図の自己点検 |
| `07_ソーススクリプト/check_soan_selfcheck_R8.9.28.py` | 素案の自己点検（検査1〜6） |

| python-docx／openpyxl／matplotlib／pypdf／LibreOffice | 読み書き・PDF化 |

**入力**　計画素案 docx・策定委員会資料 docx・試算/管理シート xlsx・
算定スクリプト群・業務工程管理表。

**出力**　①点検の結果（適合／不適合／要判断／未実施）②起票する確認事項
③対比の成果品の更新 ④素案そのものの是正。

**判定は4つに分ける。** 検出しただけで不適合にしない。

| 判定 | 意味 | 扱い |
|---|---|---|
| **適合** | 確かめて問題がない | そのまま |
| **不適合** | 直さなければ送付できない | 直してから進む |
| **要判断** | 規則には当たるが、文脈により適否が分かれる | 人が見て決める |
| **未実施** | 環境・資料がなく確かめられなかった | 合格にしない。理由を残す |

**「未実施」を「適合」に丸めない。** 走査できなかった範囲・実行できなかった
コマンドは件数として別に示す。**本町は地域支援事業のデータが未受領であり、
「未実施」に落ちる項目が現にある。** これを埋めるために推測の数値を置かない。

重大度は3段階で書く。**致命的**＝送付を止める／**重要**＝送付前に直す／
**改善**＝次の版で直す。

## 1　まず機械で確かめる

**件数・章節・未確定箇所はいつも実物から数える。** 本スキルの本文に数を書かない。
実行はリポジトリの**最上層**（`kawasaki_project/`）から行う。
スクリプトは相対パスで成果品を読むため、`07_ソーススクリプト/` に
降りて実行すると素案が見つからない。

```bash
cd kawasaki_project
S=01_第10期_最新版成果品/川崎町_計画書素案_v2.6_図表整理版.docx   # 最新版に読み替える
python3 07_ソーススクリプト/check_soan_selfcheck_R8.9.28.py "$S"
python3 07_ソーススクリプト/check_hokenryo_R8.9.30.py       "$S"
python3 07_ソーススクリプト/check_font_R8.9.30.py           "$S"
python3 07_ソーススクリプト/build_zuhyo_daicho.py
```

**終了コード0でなければそこで止まる。** 自己点検を持つスクリプトは
1件でも不適合があると終了コード1で終わる。

素案そのものを作り直すのは、**素案を直したときだけ**でよい。
既にある成果品を点検するだけなら作り直さない。
素案の版は `fix_soan_vNNN*.py` を**前の版の docx に当てて次の版を作る**
積み上げであり、最初から作り直すものではない。

docx の検証は必ず行う。検証スクリプトの場所は環境による。
**存在を確かめてから呼び、無ければ「未実施」と記す。**

```bash
V=${DOCX_VALIDATE:-/mnt/skills/public/docx/scripts/office/validate.py}
[ -f "$V" ] && python3 "$V" "$S" || echo "docx の検証は未実施（validate.py が見つからない）"
```

見出しを増減したとき、**及び本文・表・図が増減して頁が動いたとき**は
目次の頁番号を作り直す。**図の大きさを変えただけでも動く。**

```bash
python3 07_ソーススクリプト/fill_toc_pages_v200.py "$S"
```

詳しい手順とコマンドは `references/commands.md`。

**始める前に `references/pitfalls.md` を一読する。** 本業務で実際に起きた誤りと
その手立てをまとめてある。新しい点検を置く前にも読む。

**どの章節に・どの出所で・いつ時点の値で書かれているか**まで見る。

### 期待する項目は素案の側に置かない

**素案（巻末の図表番号一覧など）を正本にして対比すると、素案から項目が
落ちたときに対比も同じだけ落ちる。** 期待する項目の一覧は原典の側に持ち、
素案から読んだ一覧との差を見る。
素案から1項目を落としたときに不適合になることを、点検の受入れの条件とする。

### 語が当たっただけで「対応済み」にしない

制度改正の点検は語の走査で行うが、**当たったものは候補**である。
次を確かめてはじめて対応済みとする。

- 当たった箇所が、その事項を書くべき章節か
- 施行の時期・適用の年度が原典と合っているか
- 否定の文（「未反映である」「見込んでいない」）ではないか
- 数値・施策への反映まで及んでいるか（言及しただけになっていないか）

**「令和8年度介護報酬改定は基準年度の単価に反映されていない」という文でも
語は当たる。**

## 3　守るべき制約の走査

計画素案・委員会資料のいずれも、**本文・入れ子を含む表・ヘッダー・フッター・
テキストボックス**を走査する。走査できなかった要素は件数で示す。
偽陽性を避けるため、個人情報は値の形（正規表現）で探す。

| 見るもの | 走査する語・形 | 判定 |
|---|---|---|
| 受託者の内部の仕組み・作業経過 | 受託者／当社／ビズアップ／確認事項No／スクリプト／再実行／固定値／判定しています | 不適合 |
| 他団体の固有名称 | 大雪地区広域連合・東川町・東神楽町・上川町ほか、比較材料として読んだ団体名 | 不適合 |
| 強調記号の残り | 本文中の `**`・`__`・行頭の `- `／`#` | 不適合 |
| 版表記の食い違い | ヘッダーの `Ver.` と本文の版が違う | 不適合 |
| 禁止表現 | に由来する／と整合する／1件も／有意差がないため／全国トップ級 | 要判断 |
| 個人情報 | 電話番号・メールアドレスの形 | 要判断（公的な連絡先は文脈による） |
| 未確定箇所の表記 | ［　］以外の括弧（[ ]・【 】・〔 〕）で書いたもの | 不適合 |

**計画は川崎町が定めるものである。本文にも見出しにも受託者を主語とする語を
置かない。**

個人情報の走査は電話番号とメールアドレスに限る。
**氏名・住所・自由記述・画像の中の文字は機械では拾えない。**
委員名簿・事業所一覧・意見聴取の記録を加えるときは目で確かめる。
意見聴取の記録様式は**個人が特定されない形で計画に載せる**ことを前提に
設計してある（様式06の要件チェック・様式07の個人情報の扱いを参照）。

## 4　体裁と視認性

- 既定の段落スタイル（`Normal`）が `styles.xml` に**定義されていること**。
  無いと Word が自前の「標準」を当て、本文だけが明朝体で表示される
- 用途（章／節／▌小見出し／本文／図のキャプション／出典／表内）ごとに
  文字の大きさが1つに揃っていること。**混在させない**
- 表の見出し行を各頁で繰り返す（`w:tblHeader`）。行を分割しない（`w:cantSplit`）
- 表頭に地色を敷く
- ［要協議］［要確認］［要内訳］は本文に残す。**確定しない値を推測しない**
- **作業環境に游ゴシックが入っていないため、PDF 化した見え方は実際の Word と
  異なる。** 見え方の確認は町のパソコンで行っていただく。
  PDF は頁数・頁の割付けを数えるためだけに用いる

点検は `check_font_R8.9.30.py`（検査1〜8）による。

## 5　成果品どうしの食い違いを見る

**内容の正本は計画素案である。** 策定委員会資料・想定問答集・概要版は
素案から起こすものであり、**数値を別に持たない。**

- 素案を直したら、**同じ数値を載せている他の成果品も同じ版で直す。**
  1冊だけ直して終わりにしない（保険料の是正は素案・委員会資料・
  想定問答集・図9-1 の4か所に及んだ）
- 図の数値は `data_zuhyo.py` の1か所に置く。
  作図と図表データ管理台帳の双方がそこから読む
- 委員会資料の自己点検 `check_2kai_selfcheck_R8.9.28.py` の
  参照先を、素案の版を上げたら併せて上げる

## 6　どこまで進めてよいかの区分

| 区分 | 条件 |
|---|---|
| **協議用として送付してよい** | 機械の点検が通り、未確定箇所に既定値の扱いが定まっている。未確定箇所が残っていてよい |
| **委員会に諮ってよい** | 上に加え、目次の頁番号と紙面の点検が済んでいる |
| **公表版として確定してよい** | 上に加え、未確定箇所が0、確認事項に未解決がない、法令が定める手続（意見公募・県の意見の聴取・認知症の人及びその家族等からの意見の聴取）を経ている、対象の版が定まっている |

**確認事項の「既定値」は協議を進めるための仮置きであり、
公表の確定の根拠にならない。** 既定値は「保留」「公表の対象から外す」
「仮定を明示した協議用の試算」を選べる形にし、すべてに数値を置かない。

## 7　確認事項を起こす前に

- **同じ問いが台帳にないかを語で探す。** 台帳は `川崎町_業務工程管理表.xlsx`
  の確認事項シートを正とする
- 別の成果品で起票したら、必ず業務工程管理表へ登録する（欠番を出して確かめる）
- **番号が連続していても登録漏れは起きる。** 成果品の側で挙げた論点の集合と
  台帳の集合を突き合わせる
- **全件に「決着しない場合の当方の扱い（既定値）」を置く**
- 反映先は素案に**現にある**章節で書く（1-1〜10-4）

## 8　陥りやすい誤り

`references/pitfalls.md` に、本業務で実際に起きた誤りと手立てをまとめている。
特に次の5つは繰り返し起きている。

- **件数が0のときは、数えられているかを先に疑う**
- **同じ指標・同じ割合に2つの値や2つの分母を置かない**
- **ご指示は同じ区分の成果品すべてに当てる。1冊だけ直して終わりにしない**
- **同じ数値を2つの成果品に別々に書かない。1か所から引く**
- **雛形として複製する段落・表を、用途の合うものから採る**
  （本文の雛形に「●要点」（太字）を採ったため35段落が太字になった）
