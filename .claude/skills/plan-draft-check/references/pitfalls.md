# 計画素案の点検で実際に起きた誤り

いずれも本業務で実際に起きたものである。手立ては自己点検に置いてある。
新しい点検を置く前に一読する。

---

## 数え方・読み方

- **件数が0のときは、数えられているかを先に疑う。**
  紙面の点検が表題で表を探していたため、表題の付け方が違う報告書では
  表を1件も見ていなかった。「紙面をまたぐ表0件」は数えた結果ではなかった。
  辞書の行を `for x in r` で回してキーを見ていたため、
  町別の件数が3町とも0件になったこともある（`r.get("町")` で読む）。

- **表（ピボット）の値は、同じファイルの明細を集計した額と突き合わせてから使う。**
  給付費データの表が明細と一致していなかった。
  差の原因を外（抽出条件・住所地特例・対象月）に求める前に、
  同じファイルの中で表と明細が合っているかを確かめる。

- **「その値は原本にない」と決める前に、原本の並び順と空欄の意味を見る。**
  空欄は「値がない」ではなく「上位の行に属する」ことを表すことがある。
  並び順も情報である。

- **空欄の判定に `is None` だけを使わない。空文字列のこともある。**
  年度により同じ様式でも空欄の表し方が違う。
  数値かどうかで判定する（`isinstance(v, (int, float))`）。

- **公表資料の件数は「行数」ではなく「全国合計÷平均点」で確かめる。**

- **年度で並び順が変わる表は、位置ではなく名で突き合わせる。**
  位置で比べて別の項目どうしを比べ、誤った増減を出した。

- **内的整合の規則は、点検に使ってよいが修復に使ってはならない。**
  「単位数×10＝費用総額」は恒等ではなく、正しい値を壊しかけた。
  修復に使えるのは「要介護度別の和＝計」のように定義上必ず成り立つものだけで、
  それも欠けているのが1か所のときに限る。

- **表から値を取り出したら「セルが無い」ことと「値が0」を区別する。**
  同じ列の他の行に値があるのにそのセルだけ無いときは、読み取れていない。

## 同じものが2つある

- **同じ指標名・同じKPI番号に2つの基準値を置かない。**
  母集団・設問・分子・分母が違う値は、同じKPIの「基準値」ではなく
  「補完指標」「補足指標」と書く。

- **同じ割合に2つの分母があるときは、分母を指標名に入れる。**

- **同じ指標の名称・定義・算式・基準値を表ごとに書かない。1か所から引く。**
  同じIDが複数の表に現れる指標は辞書に持たせる（`KPI` 辞書）。

- **同じ数値を2つの成果品に別々に書かない。**
  算定スクリプトを runpy で読む形にすれば、算定を改めれば両方が追随する。
  **公表版は協議用素案を読んで組み替える**（本文・数値を別に持たない）。

- **同じ項目に2つの数え方がないかを見る。**
  合計が2つ出るときは、欠測の埋め方が違うことを疑う。

- **定員に出所が2つあるときは両方を書く。**

---

## 分母・単位・時点

- **割合の分母は「その設問に回答した票」である。**
  回収票数でも、別の設問の有効回答でもない。
  「母数」（回収率のためのもの）と「設問ごとの有効回答」（割合の分母）を分けて書く。

- **割合の表題に「〜のうち」と書いたら、その分母が実際に使われているかを
  原典の該当数から逆算して確かめる。**
  該当数÷割合で分母を逆算すれば、表題と分母の食い違いは必ず出る。

- **量の単位が「延べ人数」か「実人数」かを確かめる。混ぜて比べない。**
  単位がそろっていないものは合計もできない。

- **データの列が何を数えているかを確かめる。**
  「給付費」と書いてあっても費用額（保険請求額＋利用者負担額）のことがある。

- **月平均の値をもう一度12で除さない。桁が1つ違う値は単位を疑う。**

- **時点の違う値を足した割合を確定値として書かない。**
  表の中の数字で再計算できるかを確かめる。

- **前回調査と比べるときは母数の違いを書く。割合で比べ実数では比べない。**

## 書き方

- **推計値を実績のように書かない。「求めた」と「推計した」を書き分ける。**
  注記も併せて写す。表頭に「推計」とあるのに本文が「求めた」なら疑う。

- **検定の結果を調査設計の因果として断定しない。母集団の不一致を先に書く。**
  記号（χ²・自由度・1％点）は本文に置かず注へ回す。

- **「率が低い＝空きがある」と読まない。分母と数える対象を確かめる。**

- **「○ポイント未達」は、実績の年度と同じ年度の目標との差で検算する。**

- **「受領していない」と書く前に、受領資料一覧と自らの引用を確かめる。**
  章節を引用できているなら、本文は見ている。

- **推計の断定を避ける。**
  「達します」「収まります」→「達する見込みです」「収まる見込みです」。

## 制約（発注者指示）

- **計画の本文にも見出しにも受託者を主語とする語・内部の作業物の名を置かない。**
  「広域連合・受託者」（年次評価の実施主体）・「受託者の案とします」・
  「本素案」・「修正指示書」・「再出力を依頼中」が残っていた。
  **計画は広域連合が定めるものである。**

- **ご指示は同じ区分の成果品すべてに当てる。1冊だけ直して終わりにしない。**
  表の見出し行の繰返しを報告書には入れていたのに計画素案に当てていなかった、
  というのも同じ型の漏れである。

- **他団体の資料を比較材料として使うときは、気づいた点を原典で確かめてから書く。**
  比較材料は「当方に何がないか」を気づくために使い、
  「どう書くか」は原典から決める。記載の借用はしない。団体名は掲げない。

- **受領資料を消去するのは、ご指示があったときか作業が終わったことを
  お伝えして了解を得た後にする。** 作業の途中で自ら消去して読めなくなった。

- **レッドチームで語の有無だけを見ると偽陽性が出る。**
  個人情報は値の形（正規表現）で、禁止表現は点検方法の記述シートを除いて判定する。

- **点検の語が本文に出てこないときは、表記のゆれを先に疑う。**
  半角の「%」と全角の「％」。突合の前にそろえる。
  設問番号は `問\s*[0-9０-９]` の形で探す（「設問」の「問」に当たる）。

## 素案の構造

- **反映先として挙げた章節が計画素案に実際にあるかを確かめる。**
  存在しない節（第3章第5節）を反映先としていたため、
  既に反映済みの所見が「着手可」のまま残っていた。

- **反映済みかどうかを語の有無だけで判定しない。章節を限って判定する。**
  「除雪」「同規模保険者」は複数の章に現れる。

- **同じ指標を複数の章で扱うときは、更新を全ての章に及ぼす。**
  第3章だけ更新して第5章が古い値のまま残っていた。

- **件数・項目数を固定値で書くと実物とずれる。** 実物から数える関数を用いる。

- **過去の時点を記す資料に「現時点の値」を読ませない。**
  月次の報告書は `data_progress.snapshot(基準日)` と
  `repo_paths.draft_label_at(基準日)` を使う。

- **本文の一部を機械で落とすときは、本文末尾の節の区切りを巻き込まない。**
  `list(body.iterchildren())` には本文末尾の `w:sectPr` が含まれる。
  一緒に落とすとヘッダー・フッター・ページ番号が失われ、見た目では気づきにくい。

- **自分で書き下ろした日本語の文章は、日本語以外の文字が混じっていないかを
  機械で確かめる。** 英単語や他の言語の文字は目で読んでも見落とす。

## 確認事項

- **新しい論点を書く前に、同じ問いが台帳にないかを語で探す。**
  台帳は業務工程管理表を正とする。

- **確認事項を別の成果品で起票したら、必ず業務工程管理表へ登録する。**
  番号に欠番・重複がないかを数えれば分かる。

- **差の原因を1つに決める前に、受領資料の数値で逆算して確かめる。**
  当たらない原因を確認事項に書くと、発注者の確認も空振りになる。

- **受領資料は主要値だけでなく明細まで点検する。**
  確認事項を起こす前に、受領済みのファイルにその値がないかを確かめる。

- **画面に列があるかないかを、当方の制度知識で決めない。画面の写しから読む。**
  0 と ― は意味が違う。

## 体裁・OOXML

- **表が紙面をまたぐときは、見出し行を各ページで繰り返す**（`w:tblHeader`）。
  行の分割禁止（`w:cantSplit`）と対で入れる。

- **「第9期計画にない体裁」と決める前に、第9期の体裁を記した資料を読む。**
  【　】は第9期計画も図表のキャプションとして用いている。

- **docx・xlsx は Markdown を解釈しない。** `**` はそのまま出る。
  docx は `_runs()` で太字の run に分ける。xlsx は書式で行う。

- **`**` を機械的に落とすときは、`**` を扱うコードを壊さないか確かめる。**
  `v.replace("**","")` が `v.replace("","")` になり、
  自己点検が常に真になったことがある。累乗演算子も壊れる。

- **OOXMLは要素の順序が定められている。**
  `w:pgNumType`（cols より前）、`w:updateFields`（compat より前）、
  `w:tabs`（spacing・ind より前）、`w:bookmarkStart`（pPr の次）、
  `w:tblCellMar`（tblLook より前）、`w:shd`（tcPr では vAlign より前）。
  `w:zoom` は `w:percent` を補う。**作った docx は必ず validate.py で検証する。**

- **再出力しただけの成果品を戻すとき、本文の文字だけで比べない。**
  体裁の変更は本文の文字に現れない。zip の中身で比べる。

- **出力先を絶対パスで固定しない。** `repo_paths.py` の `RP.ROOT` を使う。
