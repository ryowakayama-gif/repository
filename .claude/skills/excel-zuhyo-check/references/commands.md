## 2　数値を直したときの影響と修正漏れ

```bash
python3 tools/suchi_impact.py                    # 直前のコミットとの差
python3 tools/suchi_impact.py --rev HEAD~3       # 指定した版との差
python3 tools/suchi_impact.py --value 6740 6436  # 旧→新を直接に指定
python3 tools/suchi_impact.py --map 6436         # その数値の所在だけ出す
python3 tools/suchi_impact.py --csv /tmp/x.csv   # 一覧をCSVでも
python3 tools/suchi_impact.py --min 4            # 4桁以上の数値だけを見る
```

修正漏れ（旧の値が他に残っている）があると終了コード1で終わる。

**直す前に `--map` で所在を出し、直したあとにもう一度実行して0件を確かめる。**

読み取りの決まり

- 数値とみなすのは、桁区切り付き・小数・3桁以上の整数である（1桁2桁は拾わない）
- 「6,740」と「6740」、「4.00」と「4.0」は同じものとして扱う
  （表示の桁数の違いを「数値が変わった」と読まないため）
- 別のファイルに同じ数値が現れているものは「移した」とみて候補から外す
- 式のセルは値が保存されていないため読まない
- 残っている箇所が30を超える数値は、別の量として偶然に同じ数が出ているとみて
  **要判断**とする。箇所の少ないものほど直し漏れである見込みが高い
- **桁の少ない整数は偶然に一致しやすい。** 騒がしいときは `--min 4` を使う

## 3　実際に起きた誤り

- **区分の参照が値の参照より1行遅く始まっていた。**
  値は見出しの次の行（3行）から、区分はその次の行（2行）からになっており、
  **棒と区分名が1行ずれて、ある団体の値が別の団体の名で出ていた。**
  表を作る関数の戻り値を使わず行番号を数え直したことによる。
  → L5（カテゴリの数と値の数が合わない）で見つかる。

- **本文に差し込む図と別冊の図表集が、同じ数値を別々に持っていた。**
  一方を直しても他方が追随せず、実際に食い違っていた
  （路線別の乗車人員の1路線、保険料の要因分解の累計4か所）。
  → 数値の出どころを1か所にする。

- **確認事項を2件増やしたのに、件数を述べた成果品を作り直していなかった。**
  2冊が「171件」のまま残っていた（件数は自動で数える作りであったが、
  **作り直していなかった**）。
  → `--map 171` で所在が出る。**作り直しを忘れると古い件数が残る。**

- **「消えた数値」を直した値と思い込んだ。**
  数値の管理の場を別のファイルへ移しただけで、
  400件近くが「消えた」と出た。
  → 別のファイルに現れているものは候補から外すようにした。
  それでも残るものは人が中身を見る。

- **表示の桁数を変えただけで「変わった」と出た。**
  「4.00」を「4.0」に改めたものが修正漏れとして出た。
  → 小数の末尾の0を落として比べるようにした。
  **表示そのものを比べたいときは、正規化せずに元の文字列で見る。**

- **xlsx は Markdown を解釈しない。** セルに `**` を書くとそのまま出る。
  セルの一部だけを太字にしたいときは書式で行う。

- **図の中の文字は機械では拾えない。**
  表題・凡例・データラベルの重なり、軸のはみ出しは紙面で見る。
