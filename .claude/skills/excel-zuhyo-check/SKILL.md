# エクセルの図表と数値の点検

数値を直すと**図表は追随するが、文章は追随しない。**
同じ数値が別の成果品にも書かれていることがある。
本スキルは、その取りこぼしを機械で見つける。

## 0　前提・入力・出力

**単体では動かない。** 対象リポジトリの次のものがあることを前提とする。

| 要るもの | 使いどころ |
|---|---|
| `tools/xlsx_zuhyo_check.py` | 図表の配置と、図と表の整合 |
| `tools/suchi_impact.py` | 数値の変更の影響と、修正漏れ |
| `tools/check_pages.py` | docx の紙面（図表が紙面をまたいでいないか） |
| openpyxl／python-docx | 読み書き |
| git | 版を比べる（`--rev` を使うとき） |

**入力**　`output/` の xlsx・docx、数値を持つソース（`data_*.py`・`build_*.py`）、
比べる版（既定は直前のコミット）。

**出力**　①点検の結果（不適合／要判断／未実施）②直すべき箇所の一覧
③確認事項として起こすもの。`--csv` を付ければ一覧をCSVで受け取れる。

**判定は4つに分ける。検出しただけで不適合にしない。**

| 判定 | 意味 | 扱い |
|---|---|---|
| **適合** | 確かめて問題がない | そのまま |
| **不適合** | 直さなければ送付・公表できない | 直してから進む |
| **要判断** | 規則には当たるが、文脈により適否が分かれる | 人が見て決める |
| **未実施** | 読めなかった・実行できなかった | 合格にしない。理由を残す |

重大度は**致命的**（送付を止める）・**重要**（送付前に直す）・**改善**（次の版で）の3段階で書く。

## 1　文字と図表が重ならないようにする

グラフ・画像は、置いた位置（錨）から列の幅・行の高さの分だけ紙面を覆う。
**覆った先に値の入ったセルがあると、印刷でもPDFでも文字が図の下に隠れる。**

```bash
python3 tools/xlsx_zuhyo_check.py                    # output の xlsx をすべて
python3 tools/xlsx_zuhyo_check.py output/ある.xlsx    # 指定したものだけ
```

- **L1 重なり**（不適合）　図が覆う範囲に値のあるセルがある
- **L2 はみ出し**（要判断）　図が表の範囲を大きく越えている

**位置の計算は目安である。** 列の幅・行の高さから求めており、
フォントにより実際の描画は動く。
**「重なりが無い」と出たことを根拠にせず、PDFに変換して紙面でも見る。**

```bash
soffice --headless --convert-to pdf --outdir /tmp output/ある.xlsx
```

図を置くときの約束

- **表の右側に置く。** 表の最終列の2列右から始める
- 表の下に置くときは、表の最終行の2行下から始める
- 1枚のシートに複数の図を置くときは、**互いの範囲が重ならない**ように
  行を十分に空ける（高さ9cmの図はおよそ24行分を覆う）
- 注記は図の下ではなく**表の下**に置く。図の高さは環境により変わる

docx の図は行内（インライン）に置く。**浮動配置にすると本文と重なる。**
図を増減したら紙面を数え直す。

```bash
D="output/ある.docx"
soffice --headless --convert-to pdf --outdir /tmp "$D"
python3 tools/check_pages.py "/tmp/$(basename "${D%.docx}").pdf" "$D"
```

## 2　図と表の数値の整合

グラフはセルを参照しているため、**表と数値が違うことは起きない。**
起きるのは**参照している範囲が表とずれている**ことであり、これは目では見つけにくい。

同じ `tools/xlsx_zuhyo_check.py` が次を見る。

- **L3 参照範囲**（不適合）　系列の値の参照が見出しのセルから始まっている
- **L4 合計の巻込み**（要判断）　カテゴリに「合計」「計」の行・列が入っている
- **L5 長さ**（不適合）　カテゴリの数と値の数が合わない／系列ごとに値の数が違う
- **L6 中身**（要判断・未実施）　参照先に数値でないセル・空のセルがある。
  式のセルは値が保存されていないため中身を確かめられない（未実施）
- **L7 内訳と合計**（要判断）　積上げの内訳の和が、同じ表の合計の欄と合わない

**L5は実際に誤りを見つけている。** 値の参照が見出しの次の行から3行、
区分の参照がその次の行から2行になっており、
**棒と区分名が1行ずれて、ある団体の値が別の団体の名で出ていた。**

直すときの勘どころ

- `titles_from_data=True` を使うと**値の参照の先頭行が系列名に使われる**。
  区分（カテゴリ）の参照は、**その次の行から**採る
- 表を作る関数の戻り値（最終行）を使い、行番号を数え直さない
- 合計の行は、内訳と並べて見せるとき以外は参照範囲に入れない

**本文に差し込む図と、別冊の図表集のグラフが同じ数値を別々に持っていないか。**
持っていると片方を直しても他方が追随しない。数値は1か所から引く。

## 3　数値を直したときの、分析の文言への影響

**図表は追随するが、文章は追随しない。**
「上回る」「最も多い」「2.0倍」といった**大小・向き・順位を述べた文**は、
数値が変わると意味が変わる。

```bash
python3 tools/suchi_impact.py                    # 直前のコミットとの差
python3 tools/suchi_impact.py --rev HEAD~3       # 指定した版との差
python3 tools/suchi_impact.py --value 6740 6436  # 旧→新を直接に指定
python3 tools/suchi_impact.py --csv /tmp/x.csv   # 一覧をCSVでも受け取る
python3 tools/suchi_impact.py --min 4            # 4桁以上の数値だけを見る
```

出るもの

1. **変わった数値**　版を比べ、消えた数値・現れた数値をファイルごとに出す
2. **文章への影響**（要判断）　消えた数値を含む文のうち、
   大小・向き・順位を述べる語を含むものを挙げる
3. **修正漏れ**（不適合）　消えた数値が他の成果品・ソースに残っている箇所

**修正の要否の判定**

| 文の種類 | 直しが要るか |
|---|---|
| 数値をそのまま述べているだけ（「6,436円です」） | 数値を差し替える。**図表から引いていれば自動で直る** |
| 大小・向きを述べている（「上回ります」「増えています」） | **向きが変わっていないかを確かめる。** 変わっていれば文を書き直す |
| 順位・最大最小を述べている（「最も高い」） | **順位が入れ替わっていないかを確かめる** |
| 差・比を述べている（「2.0倍」「340円上回る」） | **計算し直す。** 差の値も直す |
| 差の向きを施策の根拠にしている | **施策の記述まで読み直す。** 根拠が崩れていないか |

**桁の少ない整数は、別の量として偶然に同じ数が出る。**
残っている箇所が30を超えるものは要判断とし、箇所の少ないものから示す。
騒がしいときは `--min 4` で4桁以上に絞る。

**「消えた数値」は直した値とは限らない。**
表の区分を入れ替えた、年度を1つ進めた、表示の桁数を変えたといった理由でも消える。
別のファイルに同じ数値が現れているものは「移した」とみて候補から外している。
**残ったものは人が中身を見て決める。**

## 4　同じ数値の、他の記載の修正漏れ

同じ数値は複数の成果品に書かれている。
**1冊だけ直して終わりにしない。**

```bash
python3 tools/suchi_impact.py --map 6436     # その数値がどこにあるかを出す
```

直す前にこれを実行し、**出た箇所をすべて直してから**もう一度実行して
0件になることを確かめる。

直し方の順

1. **数値の出どころを1か所にする。** 算定スクリプトを `runpy` で読む、
   台帳（xlsx）から読む、辞書から引く。**書き写しをやめる**のが本筋である
2. 書き写しをやめられないものは、`--map` で出た箇所を残らず直す
3. **件数・点数は固定値で書かない。** 実物から数える
   （確認事項の件数・成果品の数・図の点数は増減する）
4. 直したあと、関わる成果品を作り直す。
   **作り直しを忘れると、古い件数が残ったままになる**（実際に起きている）

## 5　順番

```
1 図表の配置と整合     python3 tools/xlsx_zuhyo_check.py
2 数値を直す
3 図表を作り直す       （作図・成果品の生成）
4 影響と修正漏れ       python3 tools/suchi_impact.py
5 文章を直す           大小・向き・順位・差の値
6 もう一度 1・4        0件になることを確かめる
7 紙面                 PDFに変換して図表の重なりと紙面をまたぐ表を見る
```

詳しい手順と、実際に起きた誤りは `references/commands.md`。

## 6　確かめられないこと（機械では拾えない）

**「不適合0件」は「正しい」ではない。** 次は目で見る。

- 図の中に描かれた文字（表題・凡例・データラベル）の重なり・はみ出し
- 画像として貼り込んだ図の中の数値
- 数値そのものが正しいか（出所・時点・単位・分母）
- 文の意味（数値は合っていても述べ方が誤っていることがある）
- 図の見た目（軸の範囲・目盛・色の濃淡の見分け）
