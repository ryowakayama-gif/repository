## 4. 主要な発見・判断（精査レポート参照）

### 4-1. 保険料算定式は国の標準的方法と一致（検証OK）
`基準額(月) = 〔(標準給付費+地域支援)×23% + 調整交付金相当額(5%) − 調整交付金見込額 − 機能強化交付金 − 基金取崩〕÷ 収納率 ÷ 補正後被保険者数(3年) ÷ 12`
調整交付金は「5%相当を加算し実績見込を減算」する正式方式で実装（単純減算ではない）。

### 4-2. 【発見】取崩なし→取崩後の14,000千円差（要確認）
804,663 − 78,000 = 726,663 だが計画表は取崩後712,663（差14,000千円）。過年度精算・端数調整等と推察。基準額の再現が±2%に留まる主因。町の算定ワークシートで要確認。

### 4-3. 【発見】調整交付金見込率3.9%が標準5%を下回る（要確認）
川崎町は高齢化42%・後期高齢者51.6%・非課税層30%と本来5%超が見込まれる属性だが、第9期は約3.9%。実際の交付実績（介護保険事業状況報告）の確認推奨。**仮に5%なら基準額約-4%で、補正係数引上げ(+4%)と相殺** → 中心推計7,000円台は頑健。

### 4-4. 【修正済】補正係数（所得段階別加重平均料率）
非課税層30%のため実効値は1.0未満。第9期基準額から逆算し**0.96〜0.98 → 中点0.97を採用**（旧1.0は基準額を約3-4%過小評価していた）。確定は所得段階別人口（町確認待ち）。

### 4-5. 標準給付費の定義（検証OK）
標準給付費 = 総給付額 + 補完項目（特定入所者・高額介護・高額医療合算・審査手数料）。総給付額のみだと約8%過小。ワークブックは正しい定義を実装。

## 7. 技術スタック・再生成手順（`scripts/`）

### 環境
- **Word生成**: Node.js `docx` ライブラリ。実行前に `export NODE_PATH=$(npm root -g)` が必要
- **Excel編集**: Python `openpyxl`（シート名はアンダースコア、`fill`引数は必ず`PatternFill`オブジェクト）
- **チャート**: matplotlib（日本語フォント = `Noto Sans CJK JP`）

### DOCXビルドフロー（重要）
```bash
cd <workdir> && export NODE_PATH=$(npm root -g) && node build_xxx.js
# → unpack → pBdr子要素の並替(top,left,bottom,right,between,bar順) → pack --original → validate
python3 <skills>/docx/scripts/office/unpack.py file.docx unpacked
#   ↑ docx-jsが出力するw:pBdrはtop,bottom,left,right順のためregexで並べ替え必須(下記)
python3 <skills>/docx/scripts/office/pack.py unpacked file.docx --original file.docx
```
pBdr並替スニペット（各build後に必要）:
```python
import re
p='unpacked/word/document.xml'; s=open(p,encoding='utf-8').read()
order={'top':0,'left':1,'bottom':2,'right':3,'between':4,'bar':5}
def ro(m):
    e=re.findall(r'(<w:(?:top|left|bottom|right|between|bar)\b[^>]*/>)',m.group(1))
    return '<w:pBdr>'+''.join(sorted(e,key=lambda x:order[re.match(r'<w:(\w+)',x).group(1)]))+'</w:pBdr>'
new,n=re.subn(r'<w:pBdr>(.*?)</w:pBdr>',ro,s,flags=re.DOTALL); open(p,'w',encoding='utf-8').write(new)
```

### XLSXフロー（重要）
```bash
# openpyxlで編集 → recalc（単独実行・連鎖回避・タイムアウト注意）
python3 <skills>/xlsx/scripts/recalc.py file.xlsx 60
```
- **注意**: recalcを他コマンドと連鎖するとタイムアウトでファイル破損（[Content_Types].xml消失）。**必ず単独実行**
- MergedCellは読取専用 → 書込前に `ws.unmerge_cells()`、後で再マージ
- ページ設定変更後はdata_onlyキャッシュが消えるため再度recalcが必要
