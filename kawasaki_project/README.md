## 技術スタック・環境要件

### 必要な環境

- **日本語フォント**：游ゴシック（Noto Sans CJK JP）

### 標準ビルドフロー

```bash
# 環境設定（Node.js作業前に必須）
export NODE_PATH=$(npm root -g)

# 例：計画書のビルド
cd /path/to/kawasaki_project/05_ソーススクリプト
node build_plan.js

# バリデーション

# PDF変換
soffice --headless --convert-to pdf 川崎町_計画書素案_v1.0.docx

# 視覚確認
pdftoppm -jpeg -r 75 -f 1 -l 1 川崎町_計画書素案_v1.0.pdf preview
```

### 重要な技術的制約（既知の落とし穴）

1. **docxライブラリの段落ボーダー**：`top`/`bottom`のみ有効。`left`/`right`を指定するとvalidation失敗。
2. **OOXMLスキーマ順序**：`w:pBdr`の子要素順序はtop→left→bottom→rightが必要。
3. **openpyxlシート名制約**：ハイフン使用不可（数式`#NAME?`エラー原因）、アンダースコアで統一。
4. **openpyxl cell.fill**：`= None`はエラー。条件付き代入を使用。
5. **f-string内のシート参照**：シングルクォート衝突対策として、ダブルクォート構築で対応。
6. **章コンテキスト機能**：`plan_helpers.js`の`_currentChapter`。`chapterTitle(N)`後は`section`/`subsection`で章番号省略可。
7. **未確定値のIFERROR処理**：保険料試算ワークブックは基金残高等未入力でも「未算定」表示で計算エラー回避。
