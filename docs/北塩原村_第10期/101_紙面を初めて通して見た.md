# 紙面を初めて通して見た　―　頁数は「計画書」と「素案」が混ざっていた（令和8年10月20日）

点検スキル（`keikaku-check`）の手順に沿って網羅性を通した。
機械の点検は通っていたが、**スキル本文そのものが古くなっており、
そこから紙面の未確認と頁数の取り違えが見つかった。**

---

## 1　スキルの記述が古くなっていた

スキル本文にはこう書いてあった。

> 本環境では **LibreOffice が動かず docx を PDF に変換できない**。
> したがって**紙面（改頁・表の分割・図の配置）の確認はつねに「未実施」**であり、
> 成果品を送るたびにその旨を書き添える。

**これは令和8年10月10日（doc83）以降は当たらない。** 変換は行える。
10月19日には納品媒体にPDFを収める仕組みまで作っている（doc100）。
にもかかわらず**紙面は一度も通して見ていなかった。**
「つねに未実施」と書いてあるものは、誰も確かめ直さない。スキルを改めた。

## 2　頁数は「計画書」と「素案」が混ざっていた

組立てのスクリプトは `--keikaku` を付けるかどうかで**別のものを組む**。

| | 中身 | 実測 |
|---|---|---|
| **素案**（`--keikaku` なし） | 5-12「据え置いている項目の一覧」と編集注記（⚙）を**含む** | 本文145頁＋前付4頁＝**149頁** |
| **計画書**（`--keikaku` あり） | 両方を**落とす**。成果品として村に納めるもの | 本文126頁＋前付4頁＝**130頁** |
| 計画書（削減案A〜Mをすべて行う） | 同上 | 本文110頁＋前付4頁＝**114頁**（許容115頁） |

**`estimate_sakugen.py` の実測（JISSOKU）は計画書の頁数である。素案ではない。**
これに気づいていなかったため、第2回策定委員会資料の記述が実態と合っていなかった。

| | 直す前 | 直した後 |
|---|---|---|
| 資料1の配付資料一覧　別冊「第10期計画 素案」 | 約136頁 | **149頁**（実測） |
| 同　注記 | 「素案の117頁のうち…成果品としての計画書は約108頁になる見込み」 | 「別冊の149頁のうち…計画書は130頁である。仕様書の目安は約100頁であり、30頁上回る。資料8に削減案を掲げており、すべて行うと114頁になる」 |

**委員にお渡しする別冊は149頁であって、136頁ではない。** 13頁の過小申告だった。

`JISSOKU_SOAN = 145` を `estimate_sakugen.py` に置き、
`--jissoku-soan` で測り直せるようにした。
`verify_shiryo.py` の点検10 を、節ごとの切り上げによる積算ではなく
**実測と突き合わせる**形に改めた。別冊の頁数と注記の計画書の頁数の両方を見る。
どちらを壊しても落ちることを確かめてある。

## 3　紙面を初めて通して見た

`render_check.py --toushi` で本文145頁を洗い出した。

| | 実測 | 前提 |

| 表の1行の行高 | 18.35pt | 18.35pt |
| 表の幅 | 468.00pt | 468.00pt |
| 本文の高さ | 700.09pt | 700.10pt |
| 字幅（数字・漢字） | 0.50em・1.00em | 同 |

**すべて合っている。** 頁数の積み上げは組版と食い違っていない。

### 洗い出し

| 見るもの | 件数 |
|---|---|
| はみ出し（本文の枠から出ている文字・罫線） | **0件** |
| **孤立行**（表が頁をまたぎ、続きに1行しか残らない） | **2件** |
| 見出しの取り残し（節・小見出しだけが頁の最後に残る） | **0件** |
| 図の離れ（図と題・出典が別の頁に分かれる） | **0件** |
| 小さすぎる字 | **0件** |

145頁で挙がったのは孤立行2件だけだった。該当の頁を画像にして目で見た。

| 頁 | 中身 |
|---|---|
| 77 | 2-7(7)「本村の認知症の状況」の表（12行）の最後の1行 |
| 143 | 資7「主な参照資料」の表の最後の1行 |

### 2件とも直さないと決めた

- **表頭が次の頁にも繰り返される**ため（`tableHeader: true`）、読む人は見出しつきで1行を読む。読めなくはない
- 表をまるごと次の頁へ送れば孤立は消えるが、**前の頁に空白が1頁近く残る。**
  本計画は仕様書の目安100頁を30頁上回っており、空白を増やす余地がない
- **この環境には游ゴシックがなく、IPAゴシックに置き換わる。
  ここで見ている改頁は、村が Word で見る改頁ではない。**
  孤立行はフォントで動くため、置換された紙面で頁を追っても意味がない

資7の行を短くして動くか試したが、**2件のまま変わらなかった**ため、
正式名称に戻した。改頁の位置はその行の長さに左右されていない。

**納品の前に、游ゴシックの入った環境で作り直したPDFで改めて見る。**

### 控えを持つようにした

`chk_shimen.py` に今回の件数を控え、`--measure` で測り直して
**悪くなっていないか**を見られるようにした。頁の番号は素案が変わるたび動くため、
見るのは件数である。

## 5　この回で分かったこと

**「できない」と書いたものは、できるようになっても誰も確かめ直さない。**
PDFへの変換は10月10日にできるようになり、10月19日には納品媒体に
PDFを収める仕組みまで作ったのに、スキルには「つねに未実施」と書いたままだった。
**環境の制約を書くときは、いつ時点のものかを一緒に書く。**

**同じ「頁数」という語で別のものを指していた。**
素案（委員に配る）と計画書（村に納める）は19頁違う。
実測の仕組みは計画書だけを測っており、素案は測っていなかった。
**2つあるものに同じ名を付けると、片方しか測っていないことに気づかない。**

**紙面の洗い出しは、挙がった件数より「挙がらなかった」ことのほうが収穫だった。**
はみ出し0・見出しの取り残し0・図の離れ0は、
これまで一度も確かめていなかった事柄である。
