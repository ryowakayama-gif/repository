# 31　集計プログラムの構成と実行手順

北塩原村　第10期高齢者福祉計画・第10期介護保険事業計画
作成日：2026年9月8日

---

## 1　この文書の位置づけ

集計仕様書（25_集計仕様書.md／output/07）で定めた集計方針を、実際に動くプログラムにしたものである。回答データが届く前に、**ダミーデータで通しの動作を確認できる状態**にしてある。

調査票の発送は令和8年9月18日頃、回収は10月中で、村が100件程度ごとに随時送付する。第2回策定委員会は11月であり、回収から委員会まで1か月しかない。データが届いてから集計の設計を始めると間に合わないため、先に組んだ。

**回収データが届いたら、CSVのパスを指定して実行するだけで集計結果が出る。**

## 3　コードブック

調査票（令和8年9月4日版のdocx）から設問と選択肢を機械的に抽出し、集計仕様書と突き合わせた。**選択肢の文言を手で打ち直していない**ため、調査票と集計表で文言がずれることがない。

| 票 | 設問数 |
|---|---|
| 介護予防・日常生活圏域ニーズ調査 | 85 |
| 在宅介護実態調査 A票 | 28 |
| 在宅介護実態調査 B票 | 12 |
| 合計 | 125 |

| 形式 | 件数 |
|---|---|
| 単一回答 | 94 |
| 複数回答 | 23 |
| 数値 | 2 |
| 単一回答＋自由記述 | 2 |
| 複数回答＋自由記述 | 1 |
| マトリクス（親） | 2 |
| 自由記述 | 1 |

データ列は341列である。複数回答は選択肢ごとに0／1の列を作る。

### 3-1　抽出にあたって処理したこと

**ルビを読み飛ばした。** 調査票にはルビが振られており、そのまま取り出すと「のう脳そっちゅう卒中」のように読み仮名が本文に混ざる。Wordのルビ（`w:rt`）を除いて抽出している。

**表の見出しにしか選択肢がないものは手で定義した。** ニーズ調査 問5(1)の参加頻度（週4回以上〜参加していない）と、在宅調査 問9のサービス別利用状況は、選択肢が表の見出し行にあり本文からは拾えない。`shukei_codebook.py` の `OVERRIDES` と `ZAI_Q9` に定義してある。

**在宅調査 問9は12サービスに展開した。** A〜Lのサービスごとに選択肢が違う（A〜Gは週あたりの回数6段階、H〜Jは利用の有無2択、Kは月あたりの日数5段階、Lは月あたりの回数5段階）ため、1設問として扱わず12の変数に分けている。

### 3-2　調査票の番号の誤りへの対応

第2稿レビュー（27_調査票第2稿レビュー.md）で指摘した番号の誤りは、コードブックの側で読み替えている。

| 調査票の表記 | コードブックの番号 | 内容 |
|---|---|---|
| A票 問12（2つめ） | 問13 | 訪問診療の利用。問12が2つあり問13が欠番 |

**調査票そのものの修正は村側の作業である。** 印刷前に直れば読み替えは不要になるので、`ZAI_RENUM` から該当行を削除する。直らずに印刷された場合は、この読み替えのまま集計できる。

## 4　派生変数

集計仕様書のDERIVEDに沿って20変数を実装した。

| コード | 名称 | 判定基準 | 確定 |
|---|---|---|---|
| R01 | 運動器の機能低下 | 問2(1)(2)(3)のうち「3．できない」が2項目以上 | 暫定 |
| R02 | 転倒リスク | 問2(4)で「1．何度もある」または「2．1度ある」 | 暫定 |
| R03 | 閉じこもり傾向 | 問2(6)で「1．ほとんど外出しない」または「2．週1回」 | 暫定 |
| R04 | 低栄養の傾向 | BMI 18.5以下、または問3(7)で「1．はい」 | **確定** |
| R05 | 口腔機能の低下 | 問3(2)(3)(4)のうち2項目以上が「1．はい」 | 暫定 |
| R06 | 認知機能の低下 | 問4(1)「1．はい」／(2)「2．いいえ」／(3)「1．はい」のいずれか | 暫定 |
| R07 | IADLの低下 | 問4(4)〜(8)のうち「3．できない」が1項目以上 | 暫定 |
| R08 | 知的能動性の低下 | 問4(10)(11)(12)がすべて「2．いいえ」 | 暫定 |
| R09 | 社会的役割の低下 | 問4(13)〜(16)がすべて「2．いいえ」 | 暫定 |
| R10 | うつ傾向 | 問8(3)(4)のいずれかが「1．はい」 | 暫定 |
| R99 | リスク該当領域数 | R01〜R10の該当数（0〜10）。3区分にも変換 | ― |
| D01 | 疾病数 | 問8(7)の選択数（「1．ない」は0）。3区分にも変換 | ― |
| P01 | 社会参加あり | 問5(1)①〜⑧のいずれかが「月1〜3回」以上 | ― |
| S01・S02 | 支え合いの受領・提供 | 問7(1)(3)／(2)(4)で「そのような人はいない」以外 | ― |
| S99 | 孤立 | S01・S02がいずれも非該当 | ― |
| L01 | 生活機能4層 | R99・P01・認定状況の組み合わせ | ― |
| B01 | BMI | 体重kg ÷（身長m）² | ― |
| U01 | 利用サービス数 | 在宅調査 問9のA〜Lで「利用していない」以外の数 | ― |

**「暫定」としたものは、国の手引きに判定基準の明記がない。** 手引きに明記があるのは低栄養のBMI 18.5以下だけである。独自の基準を作ると県平均・全国平均と比較できなくなるため、村が「見える化」システムで用いている算出方法の提供を受けて確定させる（依頼書 管理番号24）。プログラムは判定基準を `shukei_derive.py` の1か所にまとめてあり、基準が確定したらそこだけ直せばすべての集計が連動する。

## 5　出力

`output/10_集計結果.xlsx`（8シート）

| シート | 内容 |
|---|---|
| 目次 | シート構成と回答数 |
| ニーズ単純集計 | 設問ごとの件数と％ |
| ニーズ軸別集計 | 地区・年齢階級・性別・認定状況・生活機能4層の5軸 |
| 在宅単純集計 | A票・B票の単純集計 |

| 派生変数 | 判定基準と該当数、リスク該当領域数・生活機能4層の分布 |
| 設問一覧 | コードブックの一覧 |

### 5-1　％の分母

集計仕様書の基本方針7に従い、**無回答を分母に含む**。単一回答は無回答を含めて100.0％になる。複数回答は回答者数を分母とするため合計が100％を超える（基本方針6）。

### 5-2　軸Gが未実装である理由

前回比較（軸G）は、第9期調査の集計基準と集計表の提供を受けないと実装できない。無回答の扱いと端数処理を揃える必要があるためである（依頼書 管理番号23）。プログラム上は軸Gの枠だけ用意し、データが届いた時点で追加する。

### 5-3　クロス表の実装状況

集計仕様書のX-01〜X-20のうち、軸の定義が確定している9表を実装した。残りは、自由記述の分類（X-11）、複数回答どうしのクロス（X-08〜X-10、X-13、X-14、X-17〜X-20）で、掲載の形（上位n位まで／全選択肢）を決めてから実装する。分析編の中核となるX-01・X-02・X-04・X-15・X-16は実装済みである。

## 6　ダミーデータについて

集計プログラムを本番データの前に検証するためのもので、**実際の調査結果とは無関係**である。

一様乱数にすると全員がリスク該当となり、派生変数の検算にならない。そこで、リスク判定に関わる設問には、第9期調査と全国の傾向を踏まえたおおよその重みを与えている（`shukei_dummy.py` の `WEIGHTS`）。支え合いの4設問は相互に相関するため、一定割合（4.5％）を「いずれも該当者なし」に固定している。これをしないと孤立層が0件になり、S99の算出を確認できない。

ダミーデータでの出力は次のとおりで、いずれも実務上ありうる範囲に収まっている。

| 指標 | ダミーでの値 |
|---|---|
| リスク該当領域数 0領域 | 7.7％ |
| 　同 1〜2領域 | 57.9％ |
| 　同 3領域以上 | 34.4％ |
| 社会参加あり（P01） | 50.2％ |
| 孤立（S99） | 4.2％ |
| 生活機能4層 第1層 | 2.8％ |

回答数は、ニーズ調査430件（配布約850・回収率約50％）、在宅調査96件（配布150・回収率約64％）を想定した。

## 7　実行手順

### 7-1　いまの状態を再現する

```
cd docs/北塩原村_第10期
python3 scripts/shukei_codebook.py      # コードブックの再生成
python3 scripts/shukei_dummy.py         # ダミーデータの生成
python3 scripts/shukei_run.py           # 集計の実行
```

### 7-2　本番データで実行する

```
python3 scripts/shukei_run.py \
  --needs   <ニーズ調査の入力CSV> \
  --zaitaku <在宅調査の入力CSV> \
  --out     ../../output/10_集計結果.xlsx
```

入力CSVの列名は `data/集計_コードブック.json` の「列」に合わせる。列名の対応表は集計結果の「設問一覧」シートに出力される。

### 7-3　村が100件ごとに送ってくる場合

回収の途中でも同じコマンドで走る。届いた分を1つのCSVにまとめて実行すれば、その時点の集計が出る。第2回策定委員会の資料3（調査結果速報）は、この途中集計で作る。

## 8　本番データを受け取る前に決めておくこと

| # | 事項 | 影響 | 依頼書 |
|---|---|---|---|
| 1 | リスク判定の基準（見える化システムの算出方法） | R01〜R10のすべて。県・全国と比較できるかどうか | 24 |
| 2 | 第9期調査の集計基準・集計表 | 軸G（前回比較）の実装 | 23 |
| 3 | 要介護認定データとの紐付けの可否 | 軸E（認定状況）、L01（生活機能4層）の第4層 | 21・22 |
| 4 | Web回答と紙回答のデータ形式 | 無回答の発生率が構造的に異なるため、回答方法別の集計を1回は行う（集計仕様書 §5） | ― |
| 5 | 調査票 A票 問13の番号（問12の重複） | 印刷前に直れば読み替えが不要になる | ― |

1と3が揃わない場合でも集計は動くが、リスク判定は暫定基準のままとなり、生活機能4層の第4層（要支援・要介護層）が作れない。
