## 1　順位1　紙面の推定を実際の組版に近づけた（Ⅱ-113）

### 1-1　表の列幅が自動調整のままだった

docx 側で `TableLayoutType.FIXED` を指定していなかった。Word の既定は自動調整で
あり、中身に合わせて列幅を変えてしまう。**widths で決めた割付も、頁数の推定も
当てにならない状態だった。** 素案174表・委員会資料92表を固定にした。

### 1-2　推定の誤りを2点直した

| 誤り | 直し方 |
|---|---|
| 文字の幅を `len()` で数えていた。「25,039」を6文字ぶんの幅としていたが、実際は半角数字で3文字ぶん。**数字の多い表のセルを1.5〜2倍に見積もっていた** | 全角1・半角0.5・半角の約物0.55で積算する |
| `keepNext` が表や段落の全体を引き連れるとしていた。Word の keepNext は見出しを**次の段落（表なら最初の行）**と同じ頁に置くもの。長い表の前の見出しがいつまでも送られ、**ありもしない空白を数えていた** | 連なりの最後の要素は「分割できない最初のひとかたまり」で見る |

2つめの誤りは、5-12(1)で頁の73%、資5で66%という大きな空白を生んでいた。
いずれも実在しないものだった。

### 1-3　1頁の図版の扱いを決めた

本文の高さの6割を超える図（図3-1 施策体系図）は、途中から置くと入りきらず
丸ごと次頁へ送られ、前の頁に大きな空白が残る。**あらかじめ改頁して1頁の図版と
して置く**ようにした。空白は意図したものになる。

### 1-4　計画書としての頁数

素案のままと、計画書として納める形（編集注記と5-12を載せない）を区別して
出せるようにした。

| | 頁数 |
|---|---|
| 積み上げ（送りの空白を見ない下限） | 104頁 |
| 素案のまま（送りを追う） | 115頁 |
| **計画書として** | **105頁** |
| ＋前付（表紙・本書の見方・目次） | 4頁 |
| **計画書全体** | **109頁** |
| 仕様書5①の目安 | 100頁（**+9頁**） |

点検49を新設し、2つの推定が矛盾しないこと（積み上げ ≦ 送りを追った推定）と、
計画書の頁数が目安から±20頁を超えて離れていないことを確かめている。

## 2　順位2　村の決算による図3点が見える化と一致した（Ⅱ-115）

**「見える化のD系列は区分が合わない」という当方の見立てが誤っていた。**
見える化に相手がないとしていた7図のうち3図が、受領済みのデータと
**1点のずれもなく**一致した。

| 図 | 相手 | 一致 |
|---|---|---|
| 図2-12 在宅・施設居住系別の給付月額 | D6-a・D6-b | 9点 |
| 図2-16 地域支援事業費（内訳3系列） | D48-c | 3系列×7点＋内訳の和＝合計 |
| 図2-18 保険給付費・地域支援事業費・保険料収入 | D48-b・D48-c・D47-a | 各10点 |

突き合わなかったのは**期の呼び方**のためだった。決算の系列は「平成27年3月末」の
ように**締めの日**で期を呼ぶ。平成27年3月末に締めるのは平成26年度の決算であり、
成果品の「H26年度」にあたる。1年ずらさないと1件も突き合わない。交付金の年度の
呼び方と同じ種類のずれである。歳入（保険料）D47-aだけは「H26」と年度そのもので
呼ぶためずらさない。期の正規化に、年を付けない和暦（H26・R元）を加えた。

**突合は63件から69件、突合済みの図は14図から17図**になった。
見える化に相手がない図は4図に減り、いずれも理由を記している。
