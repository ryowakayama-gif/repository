# 成果品の復元手順と、環境への依存の点検（令和8年10月4日）

金ケ崎町の案件で、**本文が版管理の外（スクラッチパッド）にのみ置かれていたため、
作業環境が作り直された時点で消えた**という事象が起きた。
同じことが本村で起きないかを点検し、見つかった弱点を直した。

---

## 1　金ケ崎町のブランチで確かめたこと

`origin/claude/金ヶ崎町高齢者` の中身を見た。

| 追跡されているもの | 件数 |
|---|---|
| 記録（`docs/kanegasaki/*.md`） | 32本 |
| 体裁（`style/figs.py`・`style/fmt.py`） | 2本 |
| **本文のモジュール（`ch_*.py`）** | **0本** |
| 成果品（docx） | 0点 |

**本文も成果品も版管理にない。** 記録のmdだけが残っている状態で、
これが「文言1か所の直しもできない」ことの中身である。

## 2　本村の状態

### 2-1　本文は版管理にある（ここが決定的な違い）

| 中身 | 置き場所 | 版管理 |
|---|---|---|
| 計画素案の本文 | `scripts/soan_content.py` | **あり** |
| 第2回・第3回委員会資料の本文 | `scripts/shiryo_content.py`・`shiryo3_content.py` | **あり** |
| 図の数値の正本 | `scripts/data_zuhyo.py` | **あり** |
| 図と節の対応 | `scripts/figures_map.py` | **あり** |
| WBS・確認事項・仕様書対照 | `scripts/wbs_*.py`・`spec_data.py` | **あり** |
| 集計の定義 | `scripts/shukei_data.py`・`shihyo_dict.py` | **あり** |
| 受領データ（見える化20冊・抽出CSV） | `data/` | **あり**（19MB） |
| 成果品（docx・xlsx 13点） | `output/` | **あり** |

版管理の外にあるのは `__pycache__` と `output/_納品媒体`（写し）だけで、
いずれも作り直せる。**本村では同じ形の事象は起きない。**

### 2-2　ただし「組み直せない」弱点が2つあった

本文が残っていても、組み直せなければ直せないことに変わりはない。
作業環境が作り直されたときに効いてくる弱点が2つあった。

| 弱点 | 中身 | 起きること |
|---|---|---|
| **置き場所のじか書き** | 19本のスクリプトが `/home/user/repository/...` を35か所にじか書き | リポジトリが別の場所に復元されると、**別の場所にある方へ書き込む**か、見つからずに止まる |
| **外部ライブラリが宣言されていない** | docx 9.7.1 が `/tmp/node_modules` にあるだけで、`package.json` もない | `/tmp` は環境の作り直しで消えるため、docxの組立て3本がいずれも止まる |

1つめは実際に起きた。複製したリポジトリで `build_soan.py` を動かしたところ、
**複製ではなく元のリポジトリの `18_計画素案.md` を書き換えた。**

## 3　直したこと

### 3-1　置き場所を1か所で決める（`scripts/paths.py`）

自分（paths.py）の位置から数える。リポジトリがどこに置かれても働く。

```
scripts/paths.py → scripts/ → 北塩原村_第10期/ → docs/ → リポジトリの根
```

`ROOT`／`OUT`／`FIGURES`／`DATA`／`BUILD` を与える。
16本のPythonと3本のJavaScriptのじか書きをすべてこれに置き換えた。
JavaScript側は `__dirname` から同じように数える。

### 3-2　外部ライブラリの版を宣言する（`package.json`・`scripts/docxlib.js`）

`docx` を `9.7.1` に固定した `package.json` を置いた。
`docxlib.js` が ①リポジトリの `node_modules` ②`/tmp/node_modules` の順に探し、
どちらにもなければ**入れ方を示して止まる**。黙って別の版で組まない。

### 3-3　組立ての途中のファイルをリポジトリの中へ

`/tmp/soan.json`・`/tmp/shiryo.json` などを `output/_build/` に移した。
`/tmp` に置くと、**複製した別のリポジトリと同じファイルを奪い合い、
片方の中身でもう片方が組まれる**。版管理には入れない。

### 3-4　点検18を新設した

次の3つを機械で確かめる。**作り直しに要るものを版管理の外に置くと通らない。**

- 組立てに要る21件（本文・体裁・データ・組立て）が版管理にあること
- 置き場所をじか書きしていないこと（`paths.py`・`docxlib.js` だけが知ってよい）
- 外部ライブラリの版が `package.json` で宣言され、版管理にあること

## 5　復元の手順（環境が作り直されたとき）

```bash
# 1 リポジトリを取得する（置き場所はどこでもよい）
git clone -b claude/kitashiobara-elderly-care-plan-i6bgzm <リポジトリ> <任意の場所>
cd <任意の場所>/docs/北塩原村_第10期

# 2 外部ライブラリを入れる（docx 9.7.1。版は package.json で固定）
npm install --prefix .

# 3 Python の道具（matplotlib は IPAGothic を使う）
#    openpyxl / matplotlib / python-docx

# 4 組み直す
python3 scripts/build_figures.py          # 図26点
python3 scripts/build_soan.py             # 素案（md ＋ 中間JSON）
python3 scripts/shiryo_content.py         # 第2回委員会資料の中間JSON
python3 scripts/shiryo3_content.py        # 第3回委員会資料の中間JSON
node    scripts/build_soan_docx.js        # 素案 docx
node    scripts/build_shiryo_docx.js      # 第2回 docx
node    scripts/build_shiryo_docx.js 3    # 第3回 docx
python3 scripts/build_zuhyo_daicho.py     # 図表データ管理台帳
python3 scripts/build_wbs.py              # WBS進捗管理表
python3 scripts/build_shukei.py           # 集計仕様書

# 5 同じものが組めたことを確かめる
python3 scripts/verify_wbs.py             # 18件
python3 scripts/verify_soan.py            # 51件
python3 scripts/verify_shiryo.py          # 21件
python3 scripts/verify_mieruka.py         # 69件
python3 scripts/verify_shukei.py          # 16件
python3 scripts/redteam_soan.py           # 要確認0件
```

点検がすべて適合すれば、同じ成果品が組めている。

## 6　金ケ崎町への申し送り

本村の作りをそのまま当てられる。要点は3つ。

1. **本文をリポジトリに追跡させる。** テキストであり容量は小さい
   （本村の本文モジュール群は合わせて約840KB）。
   これだけで「環境の作り直しで消える」事象は起きなくなる。
2. **置き場所をじか書きしない。** `paths.py` にあたるものを1本置き、
   自分の位置から数える。復元先がどこでも組み直せる。
3. **外部ライブラリの版を宣言する。** `/tmp` に入れたものは消える。

本村では、これらが守られていることを**点検18**が毎回確かめる。
同じ点検を置けば、方針が守られているかを人が覚えておく必要がなくなる。

## 7　残る前提（本村）

- **成果品の docx も版管理に置いている。** 組み直せるため必須ではないが、
  組み直す前に中身を見られる利点がある。容量は合計約5MBである。
- Python の道具（openpyxl・matplotlib・python-docx）と日本語フォント
  （IPAGothic）は環境に備わっているものを用いており、版を固定していない。
  図の体裁がフォントの版により変わる余地がある。
- **紙面の目視確認は、LibreOffice が動作せず docx→PDF 変換ができないため
  依然として未実施である。** 復元の確認はファイルの一致によっており、
  紙面を見たものではない。
