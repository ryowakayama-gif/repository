# 仕様書からのWBSの整理

作成日：2026-09-24
対象：委託第27号 仕様書（8北保福第483号 別紙）／`scripts/wbs_data.py`・`scripts/wbs_progress.py`・`scripts/wbs_kakunin.py`

---

## 1　何をしたか

WBSは仕様書を作業に分解して作ったものだが、これまで「仕様書のどの要求がどの作業に落ちているか」を逆向きに確かめたことがなかった。そこで**仕様書の側から要求事項を99件に分解**し（`scripts/spec_data.py`）、WBSとの対応を機械的に突き合わせた（`scripts/verify_wbs.py`）。

結果は次の3点である。

| | 件数 | 内容 |
|---|---|---|
| ① 仕様書にあってWBSになかった作業 | **14件** | 下記2章。WBSに追加した（100件→114件） |
| ② 参照先が存在しない確認事項 | **10種16か所** | 下記3章。WBS No. が行位置に依存していたため |
| ③ WBSにあって仕様書に根拠がない作業 | 14件 | 下記4章。削除はせず、どの条項の履行を支えるかを明示した |

あわせて**WBS No. を行位置によらない固定値に変えた**。従来は生成時の行番号から `Ⅰ-20` のように算出していたため、作業を1件挿入すると以降のすべての番号がずれ、確認事項一覧（159件・参照247か所）からの参照が静かに壊れていた。

### 2-1　このうち実務上すぐ効くもの

**Ⅰ-102 印刷の校正・校了**と**Ⅰ-101 ウェブフォームの稼働確認**は、発送予定（9/18）の直前にあって未決着の項目を抱えている。doc34で整理した印刷前の6件は9/16時点で未回答であり、Ⅰ-102 を独立した作業として立てたことで、この6件が**「入稿データの作成」の付随事項ではなく、それ自体が完了判定を要する工程**であることが管理表の上で見えるようになった。

**Ⅱ-112 策定委員会の審議意見の反映**は、第2回（11月）の後に必ず発生する工程でありながら工数を見込んでいなかった。パブリックコメントが第2回の後に回ったことで、委員会意見の反映 → パブコメ → パブコメ意見の反映 → 第3回、と反映が2回に分かれる。

## 3　参照先が存在しない確認事項（10種16か所）

WBS No. を生成時の行位置から算出していたため、作業を追加・並べ替えするたびに番号がずれていた。確認事項一覧の「関連WBS No.」247か所のうち**16か所が存在しない番号を指していた**（`Ⅰ-50`・`Ⅱ-102`・`Ⅱ-105`・`Ⅱ-108`・`Ⅲ-70`〜`Ⅲ-73`・`Ⅴ-95`・`Ⅴ-96`）。

さらに悪いことに、今回作業を14件追加したことで `Ⅱ-105`・`Ⅱ-108` は**実在する別の作業の番号になってしまう**（第2回策定委員会→必要利用定員総数、議会全員協議会→中長期保険料）。壊れていることに気づけない形の参照になるところだった。

対処は2つ。

1. **固定IDに変えた。** 現行の番号をそのまま固定値として `wbs_data.py` に書き込み、追加分は101以降を使う。以後、作業を追加・削除・並べ替えしても既存の番号は動かない。
2. **16か所を内容から正しい作業に付け替えた。**

| 確認事項 | 旧 | 新 |
|---|---|---|
| 問4(15)(16)（社会的役割）の削除の可否 | Ⅲ-71,Ⅲ-72 | Ⅰ-15,Ⅰ-102 |
| 返信用封筒の差出有効期間の延長 | Ⅲ-70 | Ⅰ-23,Ⅰ-102 |
| 調査票の印刷前修正5件 | Ⅲ-70,Ⅲ-71 | Ⅰ-15,Ⅰ-102 |
| 在宅調査票の管理番号の印字形式 | Ⅲ-70 | Ⅰ-18,Ⅰ-20 |
| 在宅が118人であることへの集計設計の対応 | Ⅲ-72,Ⅲ-73 | Ⅰ-45 |
| 交付金の該当状況調査票の写しの提供 | Ⅴ-95 | Ⅱ-65 |
| 策定委員会 現委員の任期満了と改選手続 | Ⅱ-102 | Ⅱ-80 |
| ICFを用いたクロス分析の期待像 | Ⅰ-50 | Ⅰ-95 |
| ICF分析は標準設問のみで完結するか | Ⅰ-50 | Ⅰ-95 |
| 調査票の受渡し記録の様式 | Ⅴ-96 | Ⅰ-94 |
| 自由記述の匿名化の方針 | Ⅴ-96 | Ⅰ-44 |
| 議会全員協議会で求められる関与の範囲 | Ⅱ-108 | Ⅱ-93 |
| 第2回策定委員会への調査報告書の提示範囲 | Ⅱ-105 | Ⅱ-83 |
| 第2回策定委員会の開催日 | Ⅱ-105 | Ⅱ-83 |
| 第2回策定委員会の資料の事前送付 | Ⅱ-105 | Ⅱ-83 |

あわせて、追加した作業のほうが対応先として適切な2件を付け替えた（必要利用定員総数 Ⅱ-56→Ⅱ-105、所得段階 Ⅱ-64→Ⅱ-107）。計画書の判型・レイアウトの確認事項には Ⅱ-113 を追加した。

## 4　WBSにあって仕様書に根拠がない作業（14件）

削除はしていない。いずれも**仕様書のどれかの条項を履行するために必要**であり、そのことを明示するほうが実態に合うためである。管理表の「仕様書対照」シートに、根拠の種別（手引き／確認）と、どの条項の履行を支えるかを1件ずつ書いた。

| 種別 | 件数 | 例 |
|---|---|---|
| 手引き（厚労省 実施の手引き 令和7年8月版） | 4 | リスク判定11種の算出、見える化システム登録用データの作成 |
| 確認（本業務での確認事項） | 9 | 委員の改選・委嘱、介護保険準備基金の残高・取崩方針、概要版の作成 |
| 手引き／確認 | 1 | 調査手法の決定（在宅：手法Ⅰ〜Ⅳ） |

このうち**概要版の作成（Ⅳ-92）と議会全員協議会 説明資料（Ⅱ-93）は、仕様書の成果品に記載がない**。キックオフ議事録で合意された事項であり、仕様書の範囲内か追加対応かの整理が未了である（確認事項として継続）。

唯一、根拠が「―」だった**進捗管理・課題管理（Ⅴ-100）を仕様書6(4)「協議事項」に接続した**。確認事項一覧そのものが、疑義が生じたときの協議の記録にあたるためである。

## 5　仕様書との差異として残るもの

突合の過程で、仕様書の記載と実際の運用が食い違っている箇所が3つあった。いずれも既に村と決着しているか確認中であり、記録として残す。

| 条項 | 仕様書の記載 | 実際 |
|---|---|---|
| 4Ⅰ(3) | 封筒（**配布用**・回収用）を受託者が印刷 | キックオフ議事録で**配布用は村が用意**と確定。受託者は返信用（回収用）のみ |
| 4Ⅰ(1) | 在宅介護実態調査 **約150人** | 対象者リストは**118人**（32人少ない）。クロス集計のセル数に影響 |
| 5② | アンケート調査報告書 A4両面**約100頁** | 想定**約118頁**。頁数・部数の明示がなく要確認 |
