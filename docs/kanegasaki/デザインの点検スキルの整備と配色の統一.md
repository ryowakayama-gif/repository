# デザインの点検スキルの整備と配色の統一

令和8年9月25日

**ご指摘（図5・図6で、金ケ崎町の棒が凡例では青なのに図の中に赤の棒が出てくる）は、そのとおりであった。**原因と対処、および再発を防ぐ仕組みを整理した。

---

## 1. 何が起きていたか

**系列の色を、値の大小によって変えていた。**

```
color=[RED if k < w else BLUE for k, w in zip(kg, iw)], label='金ケ崎町'
```

**「金ケ崎町」という1つの系列に凡例（青）を付けながら、県平均を下回る項目だけ赤にしていた。**そのため、凡例と棒の色が食い違っていた。**同じことが6か所にあった。**

| 図 | 何を条件で塗り分けていたか |
|---|---|
| **委員会資料 図5／素案 図17**（目標別の得点） | 金ケ崎町の棒を、県平均を下回る項目だけ赤に |
| **委員会資料 図6／素案 図21**（認知症総合支援の内訳） | 金ケ崎町の棒を、全国平均を下回る項目だけ赤に |
| **素案 図13**（地域差指数） | 金ケ崎町の棒を、0.9未満の項目だけ赤に |
| **素案 図24**（訪問介護員の提供時間） | 生活援助の棒を、60歳以上だけ赤に |
| **素案 図12**（成果指標の目標比） | 達成度を青・オレンジ・赤の3段階に（オレンジは県平均に予約した色） |
| **素案 図23**（介護職員の昨年比） | 赤が何を指すかを書いていなかった |

---

## 2. どう直したか

### 配色の規則を「1つの図の中で、色は1つの意味しか持たない」に改めた

**比較図**（本町・県・全国などの系列がある図）**では、系列の色を条件で変えない。**

| 系列 | 色 |
|---|---|
| **金ケ崎町** | **#C00000（赤）** |
| **岩手県平均** | **#ED7D31（オレンジ）** |
| **全国平均** | **#A6A6A6（グレー）** |

**下回っていることは、色ではなく `▲` と注記で示す。**図5には「▲県平均を下回る」、図6には「▲は全国平均を下回る項目」を図の中に置いた。**多系列の図では、値ラベルも系列の色にした**（金ケ崎町の値＝赤、県平均＝オレンジ、全国平均＝グレー）。

**内訳図・順位図**（本町のデータだけの図）**では、赤が何を指すかを図中か出典行に1文で書く。閾値で塗り分ける場合は2段階までとし、オレンジは使わない**（オレンジは基準線と県平均に予約する）。

**あわせて、金ケ崎町の色を全図で赤に統一した。**従前は「良好なら青、弱点なら赤」としていたが、**同じ団体が図によって色を変えることになり、読み手が色を手がかりにできない。**

## 3. 再発を防ぐ仕組み　―　スキル `docx-design`

**`.claude/skills/docx-design/` を新設した。**

| ファイル | 内容 |
|---|---|
| **`SKILL.md`** | 色・形・置き方の規則、点検の手順、ビルドの手順、文章の規則 |
| **`check_docx.py`** | **機械点検。**ビルドしたdocxと図の生成スクリプトを読んで指摘を出す |

**リポジトリ直下の `CLAUDE.md` から、成果品を触るときは必ずこのスキルを使うよう定めた。**

### `check_docx.py` が点検する内容

| 区分 | 点検 |
|---|---|
| **図の素** | **凡例のある系列に条件付きの色指定がないか**（今回のご指摘そのもの）／規定パレット外の色がないか |
| **図** | キャプションの形式と連番／画像との対応／出典の有無／`keepNext` の有無 |
| **表** | 行ごとの列数の一致／**列幅の合計が本文幅17.0cm以内**／セル幅とグリッドの一致／見出し行の塗り |
| **検算** | **「計」「合計」の行がある表について、各行の和と突き合わせる** |
| **記号** | `【　】` `【案】` `《要確定》` `《要回答》` の実数と、0-1の集計表との一致 |
| **参照** | 本文が参照する「図N」の有無／`《要確定N》` の番号が本文から参照されているか |
| **文言** | 表記ゆれ（金ヶ崎→金ケ崎、半角％→％、半角カタカナ） |

### 実行

```
python3 .claude/skills/docx-design/check_docx.py \
    out/計画素案_第10期.docx out/第2回策定委員会資料.docx \
    out/交付金の体系と本町の位置.docx out/確認事項照会_第10期.docx \
    --figs figs.py figs_soan.py
```

### 機械では見つからないもの（SKILL.mdに目視の手順として明記）

1. 図の凡例と棒・線の色が合っているか
2. **図のキャプション・出典の文言が、直前の表・段落の言い方と合っているか**
3. **表の数値と、その前後の本文の数値が一致しているか**
4. 図の軸の範囲が前後の図と揃っているか
5. PDFで図と出典・表と見出しが別ページに分かれていないか

## 4. 点検で見つけて直したもの

**初回の実行で、配色のほかに次を検出した。いずれも直したうえで、指摘0件にした。**

| 指摘 | 対処 |
|---|---|
| **表の列幅の合計が本文幅17.0cmを超える　7表**（素案4表・別冊3表） | 列幅を配分し直した。**Wordで表が右にはみ出す原因である** |
| **《要確定2》（令和30年度の保険料を幅で示すことの可否）が本文から参照されていない** | 第2章7(3)に `《要確定2》` を入れた |

**表の検算・記号の件数・参照・表記ゆれには指摘がなかった。**

## 6. 留意点

- **`check_docx.py` は「規則に反していないか」を見るものであり、「内容が正しいか」は見ない。**表の検算と記号の件数照合を除き、数値の妥当性は人が確かめる必要がある。
- **表の検算は「計」「合計」の行があり、かつその上の行がすべて数値である表のみを対象とする。**内訳の一部だけを合計している表（例：認知症高齢者の「Ⅱ以上　計」）は対象外である。
- **組版はLibreOfficeによる。**Wordでの組版とは1〜2ページずれることがある。
