## 1. やり方　―　体裁を2つのプロファイルに分けた

**`fmt.py` の体裁の値を、冒頭の辞書 `_ST` に集約した。**
**公表用のビルドだけ、`style_kohyo.py` を先に連結して `STYLE` で上書きする。**

```
公表用　　{ cat style_kohyo.py; cat fmt.py; echo; cat ch_kohyo.py; } > mkf_kohyo.py && python3 mkf_kohyo.py
その他　　{ cat fmt.py; echo; cat ch_XXX.py; } > mkf_XXX.py && python3 mkf_XXX.py
```

**関数（`P` `H1` `H2` `H3` `BUL` `TBL` `SRC` `FIG` と目次・ページ番号）は1つのままである。**
**体裁を2つに分けるために同じ処理を2か所に書くと、片方だけ直す事故が起きる。**

### 他の文書が1バイトも変わらないことを機械で確かめた

**`fmt.py` を書き換えた前後で、15文書すべての `word/document.xml` を突き合わせた。**

| | 結果 |
|---|---|
| **一致** | **15文書**（協議用素案・公表用素案・第1〜4回策定委員会資料・別表2・別表6・別冊1・別冊2・照会文書・区分文書・パブコメ資料・至急の文書・見える化の入力値） |
| 差あり | **0文書** |

**既定値が従前の値と1つも違わないことを、出力そのもので裏づけた。**

## 3. あわせて点検スクリプトを直した　―　4件

**体裁を2つにしたことで、固定値で判定していた箇所が誤って通る／誤って落ちることが分かった。**

| | スクリプト | 直したこと |
|---|---|---|
| **1** | **`check_docx.py`** | **本文幅を17.0cmの固定値から、文書の余白から求める形に改めた。**公表用（16.0cm）で列幅の超過を見落としていた |
| **2** | **`check_docx.py`** | **表の見出し行の塗りを「1F3864であること」から「規定の2色（1F3864・595959）のいずれかで、かつ文書内で揃っていること」に改めた** |
| **3** | **`check_docx.py`** | **出典行の判定を「8.5pt以下」から「本文より1pt以上小さい」に改めた。**公表用（9.0pt）を出典と認識できず、**図の出典と図の配置について39件の誤った指摘が出ていた** |
| **4** | **`mk_toc.py`** | **ページ番号の読み取りを、文字の形（「- n -」）からページ下端48pt以内の位置で拾う形に改めた。**公表用（数字のみ）で前付けの判定が壊れ、**すべての見出しが目次のページ（4ページ）に割り当てられていた** |

**4件とも、直す前は「指摘0件」または「もっともらしい数字」で通っていた。**
**体裁を増やすと、固定値で書いた点検は黙って効かなくなる。**
