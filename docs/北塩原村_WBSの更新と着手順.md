# 2. 着手順（`09_着手順`。15件）

シート名を `09_翌日の着手順` から **`09_着手順`** に、列「時間帯」を「**区分**」に改めました。従前は「令和8年10月15日（木）の打合せまで」の14件を1日の時間帯に割り振る形でしたが、**次の節目が令和8年11月の策定委員会（第2回）で1か月先であり、1日に収まる作業ではなくなった**ためです。

**策定委員会（第2回）の開催日はうかがっていません。**村の方針資料は「10月　第２回会議開催」と月のみ、村の策定委員会資料のスケジュール表には策定委員会の行そのものがありません。Ｍ-40（電話）とＭ-125のエでお伺いしています。

優先の付け方は次の3つです。

1. **村・他メンバーの回答がないと先へ進めないもの**（当方が待っている間は何も進まない）
2. **令和8年11月の策定委員会（第2回）に出す資料に直に載るもの**
3. 委員会の後でよいが、工程上必ず要るもの

# 5. 検査

着手順の表に次の検査を付けました（1つでも合わなければ生成が止まります）。

- 番号が1から順に連番であること
- 列数が見出しと一致すること
- 引いているWBS番号が実在すること（**否定試験21**：実在しない番号にすると止まる）
- 引いている照会番号が実在すること（**否定試験22**：実在しない番号にすると止まる）
- 区分が「済」で終わること ⇔ 所要が「済」であること（**否定試験23**：食い違わせると止まる）
- 「回答後」の作業には外部依存が書かれていること

照会番号の実在は、進捗管理ブックのＭ番号・Ｓ番号（`build_kitashiobara_shoukai_bun.py` の `atsumeru()`）と村資料一覧の番号の和集合で照合しています。
